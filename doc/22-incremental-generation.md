# 二进制增量生成

`--incremental` 将成功的文法分析结果序列化为二进制文件。相同分析输入再次生成时，
恢复 FIRST/FOLLOW、项集、ACTION/GOTO、展望符集合、冲突诊断及分析报告，跳过重复建表。
文法加载、合法性检查、词法编译、目标代码展开和产物组装仍使用当前输入。

```sh
ParseEngine example/cpp11_subset.gram --out-dir out/cpp11 --incremental
ParseEngine example/cpp11_subset.gram --out-dir out/cpp11 --incremental
ParseEngine example/c89_subset.gram --out-dir out/c89 --cache-dir build/parseengine-cache
ParseEngine example/cpp11_subset.gram --out-dir out/cpp11 --incremental --rebuild
```

## 开关和写盘行为

| 参数 | 行为 |
| --- | --- |
| `--incremental` | 启用分析缓存；默认位于输出目录 `.parseengine-cache/` |
| `--cache-dir DIR` | 启用增量生成，并指定可跨输出目录复用的缓存目录 |
| `--no-incremental` | 关闭缓存读写；按参数出现顺序覆盖之前的启用开关 |
| `--rebuild` | 不读取旧分析缓存，重新分析；启用增量生成时更新缓存 |
| `--check --incremental` | 可以读取已有缓存；不创建或更新缓存，不写出产物 |

默认不启用持久化分析缓存。无论是否启用，生成文件与清单在写盘前都会比较内容：
字节完全相同的文件不重写、时间戳不变，减少后续 Make/CMake 的重复编译。
用户修改过的受管理产物仍会按当前生成结果恢复；过期产物清理与用户文件保护沿用原规则。

缓存目录不登记为生成产物，`clear` 保留缓存，可在下次生成时复用。
不同文法版本按键保留独立条目；需要释放空间时可以自行清理专用缓存目录。
不要将多个进程同时生成到同一个输出目录；并行进程可以使用不同输出目录共享缓存。

## 命中与失效

分析键覆盖生成器可执行文件的 SHA-256、文法结构、终结符及其顺序、模式、展望长度、
优先级/结合性/`%prec`/`%expect`、教学配置与报告目标分类。
更新生成器、改变产生式或上述建表配置会重新分析。

LR、GLR、Earley、CYK 和 DD 模式允许只改语义动作、注释或源码位置后复用分析表。
恢复时按照规则及产生式顺序刷新动作、行号和源码偏移，目标代码重新生成，
不会执行缓存中的旧动作；同右部的不同产生式仍按各自声明位置区分。
只改词法表达式、固定字面量、空白、用户代码或输出目标配置，且未改变建表输入时，
也可以复用分析。词法和代码生成的校验仍会重新执行。

LL(0)/LL(1)/LL(k) 的左递归消除可能合并带动作的产生式，本版采用保守策略：
动作或源码位置变化会失效，完整输入重复生成可以命中。
`lex` 模式没有语法分析表，不建立分析缓存，但仍享受未变产物不重写的行为。

这是一种按依赖分类的阶段复用。修改语法结构后仍完整重建该文法的分析表，
尚未实现只更新受影响 LR 状态的算法；首次生成和词法编译也不因此自动加速。

## 二进制格式和恢复

文件名为 `analysis-<SHA-256>.bin`，按固定小端编码存储：

1. 八字节文件头 `PECACHE\0`。
2. 64 位格式版本（当前为 1）。
3. 带 64 位长度的分析键、负载 SHA-256 和二进制负载。
4. 负载包含完整分析对象与报告；整数、枚举和长度采用明确编码，不直接写 C++ 对象内存布局。

读取前限制文件不超过 512 MiB；读取时校验文件头、版本、键、摘要、各字段长度与完整消费。
损坏、截断、格式不兼容或无法读取时视为未命中，重新分析；失败的分析不发布缓存。
缓存是本地生成器的中间结果，不是接收外部不可信分析表的交换格式。

写入先使用唯一临时文件，完整关闭后原子发布。多个进程共享同一个键时，读取方只能
看到完整记录；目录不可写或发布失败时提示原因，继续正常生成解析器。
更新数据模型或序列化布局时必须提升格式版本；生成器内容摘要也会使旧构建的键失效。

## 测试文法与测量

- `example/c89_subset.gram`：现有 C89 子集，验证较大 LALR 文法。
- `example/cpp11_subset.gram`：新 C++11 语法子集，覆盖命名空间、类与继承、模板声明、
  枚举类、类型别名、`constexpr`、函数、循环、lambda、`auto`、`decltype` 和 `nullptr`。
- `example/cpp11_subset.cpp`：对应源码，回归中编译生成解析器并解析完整文件，同时测试错误源码被拒绝。

C++11 子集不执行名字查找、类型检查、预处理，不是完整 C++11 标准验证器。
没有右移运算符，嵌套模板的右尖括号使用 `> >`。

```sh
python tests/generation_cache.py
sh ci/run.sh
```

专项测试覆盖十六模式冷/热产物逐字节一致、文件时间戳、动作与位置刷新、词法修改、
结构/优先级/模式/k/教学配置失效、SHA-256 标准向量、损坏与恶意长度、只读校验、
缓存写入失败回退和并行发布。
实测总耗时与缓存大小写入 `tmp/generation-cache-benchmark.json`，用于比较本机后续版本；
不使用固定秒数作为 CI 断言，以免机器负载导致误报。

# VS Code 大文法编辑与增量生成

GramEditor 1.2 增强文档同步、诊断时序和生成任务，继续保持零 npm 运行依赖。

## 编辑与请求生命周期

插件按 UTF-16 行列收集范围变更，停手 300ms 后批量发送；同一次编辑的多个修改按
原始偏移倒序发送，多个编辑事件保持先后次序。补全、悬停、跳转等请求发出前会先
同步待发变更，避免查询旧文档。连接旧服务器时仍可以回退到全文同步。

内嵌 LSP 接收范围变更，也兼容全文替换，处理中文、emoji、CRLF 与跨行编辑。
一批变更完整验证后才更新文档；乱序版本和已关闭文档的变更不会覆盖当前状态。
同一文本版本的分词结果由悬停、补全、跳转和语义着色共用，不再每次重新扫描全文。

诊断携带协议版本；客户端同时检查编辑器版本、待同步修改和当前服务实例。
关闭后重新打开同一路径也使用递增的协议版本，旧诊断和迟到的请求结果不会覆盖新内容。
语言服务器重启使用实例代次判断，旧进程的退出事件不能清掉新连接。

请求取消会发送 `$/cancelRequest` 并释放客户端等待项、计时器和监听器；迟到响应被忽略。
服务端接收与模型处理使用独立线程，接收方可以及时记录取消和合并连续的文档变更。
尚未执行的取消请求跳过处理；已开始的请求允许完成，再返回取消状态。
关闭服务时有有限的退出等待，避免长期不响应的旧实例阻止重启。

这版实现了增量传输、变更合并和同版本扫描复用，文档变化后仍重建当前文档模型；
尚未实现只重算受影响产生式的编辑器分析。取消也不强制抢占已经开始的原生扫描。

## 生成入口

| 命令 | 行为 |
| --- | --- |
| `Gram: 生成解析器…` | 先选语言，再选支持的模式和目录，保存本工作区该文法的配置 |
| `Gram: 按上次配置增量生成` | 使用记忆的参数再次生成，无需重复选择 |
| `Gram: 按上次配置强制重新生成` | 使用相同参数并传入 `--rebuild` |
| `Gram: 选择生成配置…` | 选择设置中的具名预设 |
| `Gram: 取消全部生成任务` | 取消本扩展启动的全部生成任务 |

生成任务提供可取消的进度通知，状态栏显示缓存命中情况和总耗时。
成功的文件数量按生成器清单统计，不包含用户文件和缓存文件。
同一输出目录的并发生成会被拒绝，路径大小写和已有符号链接别名也参与判定。
取消时终止任务进程树，进程关闭后释放目录锁；不同目录可以独立生成。

目标菜单覆盖 C、C++17、Python、C#、Rust、Go、Java、JavaScript 和文法导出。
已知不支持的模式/目标组合在调用生成器前提示原因，生成器仍负责最终校验。

## 工作区配置

```json
{
  "gram.incrementalGeneration": true,
  "gram.cacheDirectory": "build/parseengine-cache",
  "gram.generationProfiles": [
    {
      "name": "C++11 子集 · GLR",
      "mode": "glr",
      "lang": "cpp17",
      "outputDir": "out/cpp11",
      "cppLexer": "vm",
      "incremental": true
    },
    {
      "name": "Java · 递归下降",
      "mode": "dd",
      "lang": "java",
      "outputDir": "out/java"
    }
  ]
}
```

增量生成默认开启；缓存目录留空时使用输出目录下的 `.parseengine-cache`。
配置中的相对路径以文法所属工作区为基准，没有工作区时使用文法所在目录。
每个文法的上次生成参数保存在 VS Code 工作区状态中，重启编辑器后仍可复用。
预设也可以指定 `strictRegex`、`teach` 和 `mermaid`；`incremental: false` 会明确关闭缓存，
即使同时配置了缓存目录也不会被重新开启。

二进制缓存格式、失效条件和首次/重复生成的差别见
[22 二进制增量生成](22-incremental-generation.md)。

```sh
node vscode/test/smoke.js
node vscode/test/extension-smoke.js
node vscode/test/p0.js
make -C library/lsp check
```

专项验证范围变更、版本乱序、重新打开文档、请求取消后的迟到响应、旧悬停过滤、
输出目录互斥、进程取消/超时、缓存命中、配置记忆和具名预设；手动校验也覆盖
Windows 中文路径与信息级诊断显示。

本批落实 P0 基础。实时正则兼容性、引用/重命名及跨文件导航、交互冲突诊断、
持续预览与样例回归、嵌入代码语言服务、文法结构与重构仍属于后续工作。

# 实验一 · 文法类型的判断

安徽新华学院编译原理课程实验报告。

## 一、实验目的

输入一个文法，输出它的四元组信息（终结符集合、非终结符集合、开始符号、产生式
个数）并判断它属于 Chomsky 文法的哪一型（0 型 / 1 型 / 2 型 / 3 型）。

## 二、实验仪器

Windows 电脑；本仓库的 **ParseEngine**（文法分析器生成器，用 C++17 写成，
`make` 即可编译）；产物用 gcc（MinGW-w64）编译。

## 三、实验原理、思路

### 3.1 四元组的三个集合怎么找

约定：**大写字母是非终结符，其余单个字符是终结符**。逐条产生式扫描左部与右部，
遇到的每个字符查一次集合，没有就加进去（`AddChar`），扫完就得到两个集合。
开始符号取**第一条产生式的左部**。

### 3.2 类型判断：从最高型往下降

按实验讲义的思路，**先假设它是 3 型**，逐条产生式检查，只要有一条不满足就降到
2 型再检查，依次向下：

| 类型 | 判定条件 |
| --- | --- |
| 3 型（正则文法） | 每条产生式都是 `A -> a`、`A -> aB`（右线性）、`A -> Ba`（左线性）或 `A -> ε`，其中 `A`、`B` 是非终结符，`a` 是终结符 |
| 2 型（上下文无关） | 每条产生式的**左部都是单个非终结符** |
| 1 型（上下文有关） | 每条产生式都满足 **\|左部\| ≤ \|右部\|** |
| 0 型（短语结构） | 左部含有非终结符即可（前面都不满足就是它） |

由于 3 型 ⊂ 2 型 ⊂ 1 型 ⊂ 0 型，从高往低逐条筛，第一个通过的就是「最符合」
的类型。

### 3.3 怎么用 ParseEngine 做

实验输入本身是一门**小语言**：一行一条产生式，左边是左部，中间是 `->`，右边是
用 `|` 隔开的若干候选式。把这门小语言写成 `.gram`（就是本实验的程序）：

> **节选**：下面是文法开头的一段，`%define` 里的运算符 / 分隔符与后面的产生式
> 没有全列出来；**完整可生成的定义见
> [`lab1_grammar_type.gram`](lab1_grammar_type.gram)**，照着片段单独生成会因为缺 Token
> 定义而报错。

```gram
%mode lalr
%tree

%token regex SYM "[A-Za-z0-9]"   /* 一个符号 = 一个字符 */
%token NL "\n"                   /* 换行是真实 Token：一行一条产生式 */
%define ARROW "->"
%define PIPE  "\|"                 /* 字面量里的 | 要转义 */

Grammar := Lines;
Lines   := Line | NL Lines | Line Lines;      /* 空行丢掉 */
Line    := SYMS ARROW ALTS NL;
SYMS    := SYMBOL | SYMBOL SYMS;              /* 左部：至少一个符号 */
ALTS    := ALT | ALT PIPE ALTS;               /* 右部：候选式用 | 隔开 */
ALT     := SYMS | %empty;                     /* 候选式可以为空 */
SYMBOL  := SYM | LP | RP | STAR | PLUS | SLASH | MINUS | EQ | LT | GT | COMMA;
```

生成出来的解析器会把输入变成一棵 **CST**（`%tree`），`%main` 里对 CST 走一遍
就拿到了全部的「谁推出了谁」：`Line` 的孩子依次是左部、`->`、若干候选式。
把每个候选式记下来，再跑 3.2 的四条判定即可。

这样词法（一个字符一个 Token、`->` 最长匹配优先于 `-`）、语法（一行的结构）都
由生成器负责，实验代码只剩「收集 + 判定」这一层逻辑。

## 四、程序代码

完整程序就是同目录的 [`lab1_grammar_type.gram`](lab1_grammar_type.gram)（词法、
语法规则 + `%main` 里的收集与判定）。生成与运行：

```bash
make                                     # 先在仓库根目录编译出生成器
build/bin/ParseEngine project/lab_report_axhu/lab1_grammar_type/lab1_grammar_type.gram \
      --lang c --out-dir out/lab1
make -C out/lab1
```

判定部分的核心（`.gram` 的 `%main` 里）：

```c
/* 3 型：A -> a、A -> aB、A -> Ba、A -> ε */
static int MatchesType3(void)
{
    for (每一条产生式) {
        if (左部不是单个非终结符) return 0;
        if (右部为空) continue;                        /* A -> ε */
        if (右部长度 == 1) { if (不是终结符) return 0; continue; }  /* A -> a */
        if (右部长度 == 2) {
            右线性 = 终结符 + 非终结符;
            左线性 = 非终结符 + 终结符;
            if (!右线性 && !左线性) return 0;
            continue;
        }
        return 0;
    }
    return 1;
}

static int MatchesType2(void) { /* 每条产生式左部都是单个非终结符 */ }
static int MatchesType1(void) { /* 每条产生式 |左部| <= |右部| */ }

/* main 里：从高往低筛，第一个命中的就是文法类型 */
if (MatchesType3())      { type = 3; }
else if (MatchesType2()) { type = 2; }
else if (MatchesType1()) { type = 1; }
else                     { type = 0; }
```

`产生式个数` 沿用了本实验原程序的口径——**按左部去重计数**（例如
`S->e|A` 只算一条），另外单独打印一行「候选式条数」作为参照。

## 五、实验结果

四个用例对应讲义里的四组输入/输出。

### 用例 1（0 型）

输入 `case1.txt`：

```text
S->ACaB
Ca->aaC
CB->BC
CB->E
aD->Da
aE->Ea
AD->AC
AE->e
```

输出：

```text
该文法为0型文法。
终结符集合: {a, e}
非终结符集合: {A, B, C, D, E, S}
开始符号: S
产生式个数: 7
（候选式条数: 8）
```

为什么不是 1 型：`CB->E` 左部长度 2、右部长度 1，不满足 |左部| ≤ |右部|；
也不是 2 型，因为 `Ca->aaC` 这类左部不是单个非终结符。

### 用例 2（1 型）

输入 `case2.txt`：

```text
S->e|A
A->aABC
A->abC
CB->BC
bB->bb
bC->bc
cC->cc
```

输出：

```text
该文法为1型文法。
终结符集合: {a, b, c, e}
非终结符集合: {A, B, C, S}
开始符号: S
产生式个数: 6
（候选式条数: 8）
```

每条产生式都满足 |左部| ≤ |右部|，但 `CB->BC`、`bB->bb` 这类左部不是单个非终结符，
所以降不到 2 型。

### 用例 3（2 型）

输入 `case3.txt`（课本上那个含括号与四则运算的文法）：

```text
S->E
E->FPF|T
P->+|-
T->TMT|F
M->*|/
F->(E)|i
```

输出：

```text
该文法为2型文法。
终结符集合: {(, ), *, +, -, /, i}
非终结符集合: {E, F, M, P, S, T}
开始符号: S
产生式个数: 6
（候选式条数: 11）
```

每条产生式的左部都是单个非终结符（2 型），但 `S->E` 的右部只有一个非终结符，
不是 `a`、`aB`、`Ba` 三种形式之一，所以不是 3 型。

### 用例 4（3 型）

输入 `case4.txt`：

```text
S->1A|1
A->0A|0
```

输出：

```text
该文法为3型文法。
终结符集合: {0, 1}
非终结符集合: {A, S}
开始符号: S
产生式个数: 2
（候选式条数: 4）
```

`S -> 1A`、`A -> 0A` 是右线性，`S -> 1`、`A -> 0` 是「单个终结符」，四条都满足
3 型。

## 六、实验总结

四个用例的类型判定与原实验程序完全一致，四元组信息（两个集合、开始符号、产生式
个数）也逐字对上了。

踩到的两个坑：

1. `%define` 的字面量里 `|` 是**多分支分隔符**，要写成 `"\|"` 才是一个竖线
   字符——第一版直接写 `"|"`，生成期报「不允许空分支」。
2. 候选式是**右递归**的（`ALTS := ALT | ALT PIPE ALTS`），遍历 CST 时必须
   继续往下走嵌套的 `ALTS`。第一版只取了直接孩子，结果每行只收到第一个候选式，
   用例 3 的终结符集合少了 `-`、`/`、`i` 三个。

# 实验五：代码优化

## 1. 实验目标

在 C-- 四元式上执行局部常量折叠、复制传播、代数化简、公共子表达式消除、活跃变量驱动的死代码删除和不可达块删除，并通过模拟输出验证优化前后语义一致。

## 2. 优化流水线

```mermaid
flowchart LR
    A["原始 C-- 四元式"] --> B["基本块局部优化"]
    B --> C["数据流求解"]
    C --> D["常量/复制传播"]
    D --> E["死代码与不可达块删除"]
    E --> F["目标代码生成"]
    F --> G["优化前后模拟对照"]
```

对常量表达式：

$$
t=2+3\Longrightarrow t=5
$$

若赋值结果在后续只有一次使用，还可继续传播：

$$
x=t,\ write(x)\Longrightarrow write(5)
$$

活跃变量分析采用迭代不动点。只有无副作用且定义结果在 `OUT` 集合中不活跃的指令才可删除；调用、写输出、跳转和返回始终保留。

## 3. 测试程序

`valid_optimize.cmm` 为：

```c
int main() {
    int value;
    value = 2 + 3;
    write(value);
    return 0;
}
```

它先由 ParseEngine 生成的 C-- 前端转为四元式，再分别以 `--no-opt` 和默认优化模式进入同一后端。

## 4. 验证方法

```powershell
t1t transfer valid_optimize.quad --asm --no-opt
t1t transfer valid_optimize.quad --asm
```

正确性条件为：

$$
Output(P)=Output(Optimize(P))
$$

同时记录四元式条数、汇编行数和模拟步数，确认优化确实改变代码，而不仅是输出相同。

## 5. 实验结果

常量表达式被折叠为立即数 `5`。四元式仍为 8 条，但 MIPS 汇编由 37 行降为 33 行，模拟步数由 17 降为 13。优化前后输出均为：

```text
输出：5
```

循环样例另外经过完整的 dataflow、SSA、GVN 和寄存器分配流程，后端报告各分析器的两种求解结果一致，最终输出仍为 `15`。

## 6. 风险控制

- `call` 视为可能修改可见状态，不跨调用传播不安全的定义；
- `write`、`read`、分支和返回具有副作用，不作为普通死代码删除；
- 不可达块删除在 CFG 上完成，跳转目标同步维护；
- 优化前后都在同一目标机模拟器中执行，避免只比较文本。

## 7. 结论

本实验从 C-- 源程序开始完成“生成解析器、语义分析、四元式、优化、MIPS 生成和模拟”的闭环。优化结果由真实执行输出验证，而非仅依据静态代码差异判断。
